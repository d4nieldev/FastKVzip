# Implementation decisions

- **D1 - Extend in place, not a supplementary table.** The user's first message ("add the full results... update the tables and figures") was ambiguous about mechanism. The agent's initial plan proposed a separate fourth table/figure to avoid touching the pipeline's hard 60x6-ratio coverage assertions. The user's second message rejected this explicitly and asked for the existing tables/figures to be extended with new columns/points instead. **Status: user-directed, superseding the agent's first plan.**
- **D2 - Coverage rule: whole-group membership, not per-cell.** A table cell or plot panel gets the two new ratios only when every task feeding it is one of the 11 SCBench base tasks (`suite.extreme_ratio_tasks` in the merged snapshot); everything else keeps exactly what it had. Table cells that don't qualify show `—`; the plot has no dash concept, so a non-qualifying panel simply keeps its original 6-point axis. This is a single data-driven rule (`set(tasks) <= extreme_tasks`) rather than a hardcoded list of which rows/panels qualify, so it can't drift out of sync with the data. **Status: agent decision, matches the user's request literally while preserving the paper's coverage-honesty conventions.**
- **D3 - Merge into the existing snapshot, not a parallel file.** `merge_extreme_scores.py` adds two ratio keys per task directly into `data/method-scores.json`'s existing `scores[task]` dicts for the 11 base tasks, rather than a sibling JSON. Provenance (job IDs, runtime commits, grid manifest hash) is recorded per method under `config.evaluation_extensions.scbench-extreme-ratios`, matching the existing `scbench-all-three-methods` entry already present from an earlier extension. Top-level `manifest_sha256`/`source_manifest_sha256s` (identifying the original 60x6 grid) are left untouched; a new `extreme_ratio_extension` block records the addition separately. **Status: agent decision following the file's own established pattern for recording extensions.**
- **D4 - Verified count: 17 panels, not 16.** The agent's plan estimated 16 extended panels (11 individual + 1 summary + 4 family panels). The actual data-driven rule found 17: the SCBench "all variants" Multi-tasking family panel has identical task membership to its "base tasks" counterpart, because neither of its two tasks (`summary_with_needles`, `repoqa_and_kv`) has a prepared length variant. This is a correct consequence of the existing taxonomy, not a bug; the plan's manual count undercounted it. **Status: verified via the rule itself (`check()` asserts extended panels == panels with `tasks <= extreme_tasks`, no hardcoded list to disagree with).**
- **D5 - Table rows: 12 of 67 extended.** The 11 individual SCBench base-task rows plus the SCBench 11-base-task mean; the other 55 rows (16 variants, SCBench 27-configuration mean, 33 RULER rows, RULER's 4 aggregate rows, the overall 60-configuration mean) show `—` in the two new columns and are otherwise byte-identical.
- **D6 - Figure 2 (context-length pooling) is unchanged and out of scope.** It requires raw per-context scores; only aggregated per-task means were pulled from W&B for the two new ratios. Recorded explicitly in the README rather than silently left out.
- **D7 - Two real bugs caught before compiling, both from the same class of mistake.** (1) The LaTeX output initially carried a literal Unicode em-dash "—" for missing-coverage cells; the document declares no `inputenc`/`fontenc`, so the classic `---` ligature is used for the LaTeX path instead (Markdown keeps the literal character, which is unaffected). (2) A new explanatory sentence contained unescaped `%` characters, which are LaTeX comment characters — this silently swallowed the rest of the sentence in the first compile ("...aggregation. The 5" then jumped straight to "Full-cache scores are method-specific."), caught only by actually compiling and reading the rendered page, not by any of the Python-level assertions. Both fixed in `render_result_tables.py`; re-verified by grepping the regenerated `.tex` for any `%` not preceded by a backslash (zero remaining) and by re-rendering the affected page. **Status: found and fixed during this implementation, not present in the final files.**
- **D8 - Validation.** `merge_extreme_scores.py --check`: 66 new values (11 x 2 x 3), diffed against a pre-merge backup — only those 66 values, 3 provenance blocks, and 3 `score_points` counters changed, nothing else. `render_result_tables.py`: regenerated table diff touches only the two new columns on the 12 qualifying rows (dashes elsewhere), footer count updated to 1,146 raw values (1,080 + 66); every data row has exactly 8 `&` separators, braces balanced, longtable/figure environments matched. `plot_retention_scores.py --check`: 98 panels, 17 extended, cross-validated against the table aggregates using the same coverage rule. All 23 regenerated plot PDFs compared against the pre-change versions after stripping PDF creation-timestamp/ID metadata: 15 fully-RULER pages are byte-for-byte content-identical; the 8 pages containing an extended panel changed only there (visually confirmed via rendered PNGs). Full `latexmk` compile via the TeX Live install already present on this machine (`~/.cache/codex-runtimes/codex-texlive/full`, discovered rather than installed): 47 pages (unchanged from the prior extension), zero errors, zero undefined references/citations after the final pass, one pre-existing benign underfull-hbox warning on a URL line (present before this change too). The extended table and retention-curve appendix pages were rendered to PNG and visually inspected. **Status: completed.**
